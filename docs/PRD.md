## 1. 배경 & 문제 정의

### 1.1 현재 제품 (As-Is)

**"내한공연 트래커"** — 일본 아티스트의 **공식 내한공연** 일정·티켓오픈 정보를
크롤링·수집해 대중에게 보여주는 공개 디렉토리.

- 소비자(관객) 중심: "언제 어떤 공연이 있고 티켓은 언제 열리나"를 알려줌
- 운영 주체: 서비스 관리자 **1명**(`ADMIN_EMAIL`)이 공연/아티스트를 CRUD

### 1.2 새로 풀려는 문제 (To-Be)

대학 뮤지컬·합창 동아리, 소규모 공연 단체의 **운영진**은 공연 하나를 올리기 위해
이런 일을 동시에 처리한다:

- **공연 홍보** — 포스터·소개·일시·장소·출연진을 담은 페이지를 만들어 SNS로 뿌림
- **단원 모집** — 모집 공고 → 지원서 접수 → 오디션 일정 조율
- **연습 일정 관리** — 연습 일정 공유, 단원 참석 체크, 가능 시간 조율
- **예매** — 관객이 좌석/입장을 신청하고 운영진은 명단을 관리
- **공지사항 전달** — 단원·관객에게 공지를 올리고 알림 발송

지금은 이걸 카톡·구글폼·엑셀·인스타 DM으로 흩어서 처리한다. **한 곳에서 처리하는
도구**가 없다.

### 1.3 두 제품의 관계

|             | 내한공연 트래커 (기존)                                    | 사설 공연 운영 (신규) |
| ----------- | --------------------------------------------------------- | --------------------- |
| 주 사용자   | 관객                                                      | 운영진 + 단원 + 관객  |
| 데이터 출처 | 크롤링 + 관리자 입력                                      | **단체가 직접 입력**  |
| 성격        | 읽기 위주 디렉토리                                        | 멀티테넌트 운영 SaaS  |
| 공통 자산   | 캘린더, 공연 상세, 알림(이메일·푸시), 인증(Supabase), PWA |

→ **기존 인프라(캘린더·알림·인증·PWA)를 재사용**하되, "단체(org)"라는 소유
주체와 역할 기반 권한을 새로 얹는다.

## 2. 목표 & 비목표

### 2.1 목표

1. 단체 운영진이 **로그인 → 공연 개설 → 홍보 페이지 발행**까지 10분 내 완료
2. 관객이 **로그인 없이도** 홍보 페이지에서 **예약**을 남길 수 있음
3. 운영진이 **공지 1건으로 단원·예약자에게 이메일/푸시** 발송
4. 기존 내한공연 트래커 기능은 **그대로 유지**(회귀 없음)

### 2.2 비목표 (이번 범위 아님)

- 유료 결제·정산 (A2 기본값 기준, Phase 2 이후)
- 좌석 지정(좌석도) 예매 — 초기엔 인원수 기반
- 단체 간 정산/수수료 모델
- 모바일 네이티브 앱(현 TWA/PWA로 충분)

| ------------------------ | -------------------- | ---------------------------------------------------------------- |

### 4.2 신규 기능

#### F1. 단체(Organization) — ✅ 구현됨 (Phase 1)

- F1.1 로그인 사용자가 **단체를 생성**(이름·소개·로고·핸들). 생성자는 자동으로
  **owner**.
- F1.2 단체는 고유 핸들로 **공개 프로필 페이지**를 가짐: `/o/:handle`
- F1.3 **역할**: owner / staff(운영진) / member(단원). owner·staff는 관리 권한,
  member는 열람·참석.
- F1.4 초대 링크(또는 코드)로 단원/운영진 추가.

#### F2. 공연 홍보 페이지 — ✅ 구현됨 (Phase 1)

- F2.1 단체가 공연을 개설(제목·소개·일시·장소·포스터·출연진·가격·문의). **기존
  performances 테이블 확장**.
- F2.2 공개 상세 페이지에서 포스터·소개·타임테이블·출연진·예약 버튼 노출.
- F2.3 **공개/비공개 토글**(A3). 공개 시 메인 캘린더·검색에 `[동아리]` 유형
  배지로 통합 노출.
- F2.4 SNS 공유(OG 이미지) — 기존 `opengraph-image` 패턴 재사용.

#### F3. 예약(Reservation) — ✅ 구현됨 (Phase 1)

- F3.1 관객이 **로그인 없이** 이름·연락처·인원수·회차 선택으로 예약.
- F3.2 회차별(show_times) **정원 설정 및 잔여석 자동 계산**.
- F3.3 운영진 대시보드에서 예약 명단 조회·상태 변경(확정/취소/노쇼)·**CSV
  내보내기**.
- F3.4 예약 확인 이메일 자동 발송(선택: 취소 링크 포함).
- F3.5 💭 결제 필드(price·payment_status)는 컬럼만 두고 Phase 2에 PG 연동.

#### F4. 공지사항 — ✅ 구현됨 (Phase 1, 이메일) · 🔜 웹푸시 후속

- F4.1 운영진이 공지 작성(제목·본문·대상: 단원/예약자/전체). ✅
- F4.2 대상에게 **이메일** 발송(Resend, 중복발송 방지). ✅ / **웹푸시는 후속** —
  현 스키마상 org 멤버·예약자를 웹푸시 구독(익명 subscriber 기반)과 연결하는 매핑이
  없어 Phase 1.5로 분리. 🔜
- F4.3 공지 목록을 단체 페이지(전체공개)에 노출. ✅

#### F5. 단원 모집(Recruitment) — 🕓 Phase 2

- F5.1 모집 공고(모집 파트·인원·마감일·설명).
- F5.2 지원서 폼(이름·연락처·지원 파트·자기소개·첨부).
- F5.3 지원자 목록·상태 관리(서류통과/오디션/합격/불합격) + 결과 통보 메일.

#### F6. 연습 일정 관리(Rehearsal) — 🕓 Phase 2

- F6.1 연습 일정 등록(일시·장소·대상 파트).
- F6.2 단원 참석 체크(참석/불참/미정) — 출석 스탬프(E7) 로직 재사용.
- F6.3 💭 가능 시간 조율(when2meet 스타일) — Phase 3 검토.
